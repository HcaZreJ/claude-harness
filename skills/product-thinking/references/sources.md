# 一手来源学习地图

按学派组织。每条给：核心主张 → 反直觉点 → 读什么。标注（转述）的条目未核实到逐字原文，引用时按概念转述处理。

## 学习路径

治「只从技术角度看产品」，按梯队读；每读完一本或一篇，找一个身边的产品套用一遍再读下一个。

1. **第一梯队 · 换掉出发点**（约一周）：《The Mom Test》（两小时读完，从此改掉「问别人觉得我的想法好不好」）；Melissa Perri 的 The Build Trap 博文（把「造了多少」和「解决了什么」分开）；Paul Graham 的 Do Things That Don't Scale 与 How to Get Startup Ideas；Superhuman PMF 引擎一文（把「有没有 PMF」从玄学变成可执行循环）。
2. **第二梯队 · 建立框架**（一到两个月）：《俞军产品方法论》（交易视角与用户价值公式）；梁宁《产品思维 30 讲》（体验分层与痛点定义）；Cagan《Inspired》（四大风险与产品发现）。
3. **第三梯队 · 专项补强**（按需）：定位读 Dunford《Obviously Awesome》；定价读《Monetizing Innovation》；需求本质读 JTBD 材料；判断力读 Shreyas Doshi 的访谈与 thread。

进步的度量（Lenny 的科学方法）：每次产品判断前先写下假设与预期结果，事后复盘对错。进步 = 预测准确率在提高，且能在评审里先于别人指认最弱一环；凭感觉说「我进步了」不算。

## 中文一脉

### 俞军 ·《俞军产品方法论》

- 核心主张：产品即交易——用户用行为投票，每次使用都是一次「付出成本换取价值」的交易。用户价值 = 新体验 − 旧体验 − 替换成本；用户不是自然人，是需求的集合（同一个人在不同场景是不同用户）。
- 反直觉点：产品经理天赋排第一位的是批判性思维，不是同理心——没有批判性思维的同理心只会收集到用户自己都说不清的伪需求。
- 读什么：《俞军产品方法论》全书；[ifanr 深度对话俞军](https://www.ifanr.com/863623)（一手访谈）。

### 梁宁 ·《产品思维 30 讲》（得到课程）

- 核心主张：用户体验五层——感知层 / 角色框架层 / 资源结构层 / 能力圈 / 战略存在层，问题出在哪层就修哪层，UI 改版治不了战略层的错位。确定性产生依赖：留存的杠杆是「每次用都能预期发生什么」，不是功能数量。点线面体：个体的点，价值取决于附着在哪条正在扩张的线/面/体上。
- 反直觉点：痛点不是难受，是恐惧（错过、失去、丢脸）——这个更窄的定义能过滤掉大量「用户抱怨的不方便」型伪痛点立项。
- 读什么：得到课程《梁宁·产品思维 30 讲》；网上笔记版本多为二手，用于定位后回原课程听。

### 张小龙 · 两场演讲

- 核心主张：好产品用完即走——互联网的使命是帮人提高效率，不是让人把时间耗在应用里；微信团队从未瞄准 KPI 工作。评审排查顺序：有趣 > 功能 > 交互 > UI，前一项不成立不看后一项。
- 反直觉点一：「克制」这个词从来没在他脑袋里出现过——每个被砍掉的功能都有一条具体的「为什么行不通」，砍功能是逐个证伪的结果，不是价值观姿态。把「少做功能」归因为克制/极简，等于免除了尽职调查。
- 反直觉点二：对于新点子，99% 的情况下否定是对的——产品经理的默认姿态是否定，反驳不倒再推进。
- 读什么：[2012 年 8 小时演讲「微信背后的产品观」实录](https://blog.csdn.net/qq_39108466/article/details/79320859)；[2019 微信公开课 4 小时演讲 3 万字实录](https://www.digitaling.com/articles/96207.html)；[否认「克制」的现场速记](https://www.fromgeek.com/fintech/69725.html)。

### 苏杰 ·《人人都是产品经理》

- 核心主张：Y 模型——用户需求（原话，常常是错的方案）→ 追问 Why 得到用户目标 → 产品功能；再深一层通到人性/价值观（宝马加长车型满足的不是空间，是身份表达）。判据：用心听，但不要照着做。
- 读什么：《人人都是产品经理》Y 模型章节；[需求分析的 Y 理论](https://www.woshipm.com/pmd/76380.html)。

### 王诗沐 ·《幕后产品》（转述）

- 核心主张：作为网易云音乐的产品负责人，他的路径是直觉负责提出候选方向（「懒人需要免搜索的音乐发现」），数据和调研负责证伪候选——两者分工在不同阶段，不要要求数据「跑出」方向。
- 读什么：《幕后产品》第三章需求分析方法论。本条全部来自二手转述、原书未核实，引用时降权。

### 纯银（郭子威）

- 核心主张：产品经理不如产品模型重要——方向、定位、策略组成的产品模型通常源自创始人的独特理解；先判断产品是资源驱动、运营驱动还是产品驱动，只有产品驱动型才值得为「产品判断力」单独付费。（他的三分法回答「要不要为产品判断力付费」这个人事决策；SKILL.md 反模式表里的评价维度分型回答「用什么标准评价产品」——两者问的是同一件事：这个产品靠什么赢。）
- 反直觉点：一罐复盘——「十倍目标是万恶之源」（融资承诺绑架产品节奏）；原型测试无法验证规模化后产品模型是否成立，早期数据好看不构成模型成立的证据。
- 读什么：[产品经理重要吗？](https://www.jianshu.com/p/b80e98f2dda3)（一手）；一罐创业复盘报道。

### woshipm.com 淘金指南

高质量与水文并存，判断标准一条：**一篇文章的价值 = 能从中带走的「下次遇到类似情况该做的动作」；读完带不走动作的，这个作者的后续文章直接跳过。**三类糟粕（多数扫开头两段即可识别）：只复述经典案例不产出方法的（福特「更快的马」被复述千遍）；概念正确但案例是编造的框架文；十条形容词式清单文。值得读的具体几篇：

- [如何区分真需求和伪需求](https://www.woshipm.com/share/6418582.html)——土办法判据的出处
- [如何提高产品思维能力：四个训练方法](https://www.woshipm.com/pmd/711382.html)——关键用户行为五层分析
- [一篇文章带你入门产品经理（2026）](https://www.woshipm.com/pmd/6465006.html)——五问 + 七问清单的出处
- [掌握用户思维的四点技巧](https://www.woshipm.com/operate/5260253.html)——思考路径反转、腾讯 10/100/1000 原则
- [B 端与 C 端产品思维的本质区别](https://www.woshipm.com/share/6330710.html)——B/C 诊断句的出处
- [新人产品常犯的 7 个错误](https://www.woshipm.com/zhichang/6244487.html)——每条配触发场景与改进动作
- [一文读懂互联网产品商业化](https://www.woshipm.com/operate/5145543.html)——收入漏斗拆解与体验红线

## 西方一脉 · 产品发现与组织

### Marty Cagan ·《Inspired》《Empowered》（svpg.com）

- 核心主张：四大风险——value（会不会买）/ usability（会不会用）/ feasibility（能不能做）/ viability（业务上成不成立），多数团队只评 feasibility，viability 常年没人负责。Discovery 与 delivery 由同一群人做，设「研究团队→文档→开发团队」的交接即反模式。
- 反直觉点：把排好优先级的功能清单发给团队 = 负责任的管理？恰恰相反，这正是团队沦为 feature team（雇佣兵）的根源；被赋权团队拿到的是问题和成果目标，不是功能清单加日期。
- 读什么：[The Four Big Risks](https://www.svpg.com/four-big-risks/)、[Discovery-Delivery](https://www.svpg.com/discovery-delivery/)、[Empowered Product Teams](https://www.svpg.com/empowered-product-teams/)（全部一手）。

### Melissa Perri ·《Escaping the Build Trap》

- 核心主张：build trap = 把「发了多少功能」当价值的代理指标；破解 = 把团队日常对话从「今天交付了什么」换成「今天学到了关于客户/业务的什么」。
- 反直觉点：团队很忙、迭代很快、看起来高产，恰恰可能是 product death cycle 的表现——忙与有效是两件事。
- 读什么：[The Build Trap 原文](https://melissaperri.com/blog/2014/08/05/the-build-trap)（一手）。

### Teresa Torres ·《Continuous Discovery Habits》（producttalk.org）

- 核心主张：机会解决方案树——Outcome → Opportunity（来自访谈，不来自头脑风暴）→ Solutions → Assumption Tests；持续发现 = 做产品的这群人每周至少接触一次用户。
- 反直觉点：发现的价值在于团队亲自形成判断——独立调研团队做完转交一份报告，价值大打折扣。
- 读什么：[Opportunity Solution Trees](https://www.producttalk.org/opportunity-solution-trees/)（一手）。

### Dan Olsen ·《The Lean Product Playbook》

- 核心主张：PMF 金字塔——底两层是市场（目标客户、未被满足的需求），上三层是产品（价值主张、功能集、UX）；团队在功能集或 UX 层争执不下时先回查底层，多半是目标客户或需求本身没定清。机会 = 重要度高 × 满足度低的象限。
- 反直觉点：「客户提得最多」≠「满足度最低」——声音大的需求可能已被竞品做得不错，资源该去「重要且不满足」处。

### Amazon · Working Backwards / PR-FAQ

- 核心主张：立项前先写未来发布的新闻稿 + FAQ；FAQ 强制自答「这个产品失败的三大理由」「单位经济模型」「TAM」。新闻稿打动不了自己人，方案在写代码前毙掉。
- 反直觉点：速度 = 有方向的快——前期写文档看似慢，是后期加速的前提（AWS 上线前 PR-FAQ 打磨超一年）。
- 读什么：[Working Backwards PR/FAQ 模板与说明](https://workingbackwards.com/resources/working-backwards-pr-faq/)（前 Amazon 高管，权威）。

### Basecamp ·《Shape Up》（全文免费）

- 核心主张：appetite——先拍板愿意花多少（1-2 周或 6 周），让设计和范围适配数字；固定时间、可变范围。
- 反直觉点：deadline 不是外部强加的坏事，是逼出高质量范围取舍的设计工具——没有 deadline 反而做不出取舍。
- 读什么：[Shape Up 第三章 Appetite](https://basecamp.com/shapeup/1.2-chapter-03)（一手）。

## 西方一脉 · 需求本质与验证

### Clayton Christensen / Bob Moesta · Jobs to be Done

- 核心主张：人们雇佣产品来完成任务——job = 某人在特定情境下想取得的进展。四力模型：切换发生当且仅当 push + pull > anxiety + habit；需求由挣扎时刻创造。
- 反直觉点：产品好不构成用户会换的证据——anxiety 和 habit 经常大到吃掉再好的 pull。
- 读什么：Christensen [Marketing Malpractice](https://hbr.org/podcast/2016/12/the-jobs-to-be-done-theory-of-innovation)（HBR）；[The Four Forces](https://jobstobedone.org/the-four-forces/)（Moesta 一手）。

### Rob Fitzpatrick ·《The Mom Test》

- 核心主张：三规则——谈他们的生活不谈你的想法；问过去的具体行为不问未来意愿；少说多听（说话超过三分之一就是在推销不是在学习）。三类假阳性要打折：夸奖、泛化意愿（fluff）、功能建议（ideas）。访谈成功的验收标准 = 拿到有代价的下一步承诺（commitment & advancement）。
- 反直觉点：「一说出你在做什么，对话就被污染了」——描述自己的想法是访谈里信息量最低的动作。
- 读什么：《The Mom Test》全书（很薄，两小时读完）。

### Sean Ellis + Rahul Vohra（Superhuman）· PMF 度量

- 核心主张：唯一问题「如果不能再用这个产品你有多失望」，≥40% very disappointed 是 PMF 的方向性阈值。Superhuman 四步引擎：调查 → 分群 → 分析 → 改进，只深听高期望用户（HXC），roadmap 一半加强已被爱的、一半清除 somewhat disappointed 用户的具体障碍，一年从 22% 到 58%。
- 反直觉点：主动放弃「not disappointed」用户的意见权重是杠杆所在——同时讨好三类人会把 roadmap 摊薄成四不像；只改统计口径（剔除非目标用户）分数就从 22% 跳到 32%。
- 读什么：[How Superhuman Built an Engine to Find Product-Market Fit](https://review.firstround.com/how-superhuman-built-an-engine-to-find-product-market-fit/)（Rahul Vohra 一手，必读）。

### Paul Graham · Essays（全部一手、免费）

- 核心主张：Make something people want；深井胜过浅坑——少数人极度想要胜过多数人觉得还行（Microsoft 给几千个 Altair 用户写 Basic、Facebook 只开放哈佛）；早期靠创始人手摇曲柄逐个招募服务用户（do things that don't scale）；「活在未来，然后补上缺失的东西」。
- 反直觉点：schlep blindness——优质机会常年没人做，因为解决它要蹚枯燥不体面的浑水（Stripe 之于银行合规），创始人会不自觉对这类机会视而不见。
- 读什么：[Be Good](https://www.paulgraham.com/good.html)、[Do Things That Don't Scale](https://www.paulgraham.com/ds.html)、[How to Get Startup Ideas](https://www.paulgraham.com/startupideas.html)、[Schlep Blindness](https://www.paulgraham.com/schlep.html)。

### Kano 模型

- 核心主张：对每个特性正反两问（有它感觉如何 / 没它感觉如何），交叉得出 must-be / performance / delighter / indifferent / reverse 五类。
- 反直觉点：delighter 是会贬值的期限资产（手机摄像头、酒店 WiFi 都从惊喜退化成理所当然，且退化在加速）——delighter 的验证结论有保质期要复检，must-be 只会更严不会松动。

## 西方一脉 · 商业化与判断力

### April Dunford ·《Obviously Awesome》

- 核心主张：定位五段链，严格按序推导——竞争性替代品 → 独特属性（替代品做不到而我们做得到的）→ 价值与证明 → 目标细分 → 市场品类。起点是「如果我们不存在，客户拿什么顶替」。把自己放进客户已理解、已有预算的品类，比发明新词更快拿到购买意愿。
- 反直觉点：定位不是发布前的包装工序，是产品往哪长的共同起点——常见做法把它留给营销部门收尾，顺序反了。

### Madhavan Ramanujam ·《Monetizing Innovation》

- 核心主张：在设计产品之前验证付费意愿；WTP 对话钉住具体价格问（什么价划算 / 什么价贵但接受 / 什么价直接不考虑）。功能分 Leader / Filler / Killer。四种定价失败：feature shock（堆功能没有价值故事）、minivation（定价过低反而显得不值钱）、hidden gem（该收费的核心价值免费送掉）、undead（没人付费靠惯性续命）。
- 反直觉点：「免费增值当获客钩子」的直觉常常正是 hidden gem 陷阱——不是慷慨，是定价失误。

### Shreyas Doshi

- 核心主张：product sense = 同理心 × 领域知识 × 创造力，可训练非天赋。Pre-mortem：项目开始时假设已失败、反推原因，用三栏分开真老虎 / 纸老虎 / 大象（没人敢说的显而易见的问题）。LNO：任务按杠杆分级，Overhead 直接消灭不是优化。
- 反直觉点：大多数执行问题其实是战略问题——团队「做不完、太忙」时先回查目标选错没有，不是先加人。
- 读什么：[Lenny's Podcast 访谈](https://www.lennysnewsletter.com/p/episode-3-shreyas-doshi)；他的 pre-mortem thread。

### Ben Horowitz · Good PM / Bad PM（1998）

- 核心主张：好 PM 清晰定义「做什么」而非纠结「怎么做」；对结果负全责不找借口；把团队焦点放在营收和客户上；宁可把话说得太明白也不含糊。
- 读什么：[a16z 版原文](https://a16z.com/good-product-manager-bad-product-manager/)（一手，27 年后仍可直接当自查表）。

### Lenny Rachitsky（lennysnewsletter.com）

- 核心主张：product sense = 持续做出对用户产生预期影响的产品决策的能力；训练路径是「提假设 → 设计实验 → 复盘」的科学方法，不是凭感觉。B2B 场景价值主张的措辞能让付费意愿摆动 ±20%（C 端 ±15%）——B 端客户需要可复述的购买理由。

## 刻意练习（怎么把这些内化）

1. **拆解产品**：挑一个常用产品，假装自己是它的 PM。先自己回答（不看它的实现）：关键用户行为是什么？为什么用户愿意投入？怎么增加完成关键行为的人数？想不出更多了，再对照它的真实做法，找出「它想到我没想到的」与「我想得更好的」。
2. **关键行为五层追问**：为什么用户产生这个行为 → 它给用户什么可传播的优越感 → 现在的设计是效率最高的吗 → 能延伸出什么变现 → 如何让更多用户完成它（最重要的一问）。
3. **场景压力测试**：主场景依赖什么第三方或特殊条件？门槛被第三方控制的场景是高风险场景（维诺城案例，见 cases.md）。
4. **数据多问为什么**：指标波动时把「新用户/老用户/付费/非付费/流失前的用户各做了什么」拆开对照；数据不是用来看的，是用来回答问题的。
